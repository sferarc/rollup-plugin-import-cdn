# The plugin targets Node only

Recorded 2026-10-21, from item 8 of [[plans/2026-10-20-plugin-gaps]].

## Decision

Running outside Node is not planned until someone asks. Rollup plugins run where Rollup runs, and that is Node in practice. The Node built-ins stay as top-level imports: `node:crypto`, `node:fs/promises` and `node:path` in `src/load.ts`, `node:crypto` in `src/integrity.ts`, `node:fs`, `node:module` and `node:path` in `src/index.ts`.

## Why

No user has asked for a browser or edge build of Rollup with this plugin. Supporting one means a lazy import for the cache, WebCrypto for integrity (which is async, so the digest path changes shape), and a replacement for the entry stat and builtin list in `src/index.ts`. That is real churn and new test surface for an unrequested case.

## How it could be undone by accident

Adding a Node-only import to a module is harmless today; this decision only says nobody should spend effort removing them. The `engines` field and the `fetchImpl` error text already tell users to run on a Node version with global `fetch` ([[architecture/overview]]).

## What would reopen it

A request from someone running Rollup outside Node. The work list is the one in the "Why" section.
