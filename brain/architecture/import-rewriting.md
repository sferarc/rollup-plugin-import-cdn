# Import rewriting

`loadHook(key, options)` in `src/load.ts` gets the module through `resolveDependency` ([[resolution]]), then rewrites the specifiers that need a base URL (`./x`, `../x`, `/x` and `//host/x`, matched by `isRelativeReference`) into absolute URLs, which the plugin's own `resolveId` then claims on the next round. Bare specifiers stay as written, so they reach `resolveId` as package names and `versions` and `priority` apply to them; before #15 they were resolved against the CDN module's URL and fetched as is, past both options (`src/load.test.ts`, "should leave bare specifiers for resolveId").

Inside the plugin this is not a second download: `importCdn` in `src/index.ts` memoises each fetch by URL until the next `buildStart`, so `load` reuses the response `resolveId` already fetched for the same id (#14; `src/index.test.ts`, "fetches a module once for resolveId followed by load", "refetches after buildStart"). Calling `resolveDependency` or `loadHook` directly, outside the plugin, has no memo and fetches every time.

## Steps

1. `await init()` and `parse(source)` from `es-module-lexer/minimal`. The minimal entry keeps the v2 record shape with `s` and `e` specifier offsets; see [[decisions/2026-09-14-es-module-lexer-minimal]].
   If `parse` throws, `loadHook` rethrows `[rollup-plugin-import-cdn] Could not parse <name> from <response url>: <lexer message>` with the lexer error as `cause`, and adds a note that the CDN returned HTML when the source starts with `<` after whitespace. Before this the build failed with the lexer's bare `Parse error @:<line>:<col>`, which named neither the package nor the URL (#27; `src/load.test.ts`, "should name the module and URL when the CDN returns HTML", "should name the module and URL when the source has a syntax error"). An HTML body the lexer happens to accept, such as `<!doctype html><html><body>hi</body></html>` with no quotes or brackets, still passes through unchanged as module code.
2. Records with `d === -2` are `import.meta`, whose span is the expression rather than a specifier, and are skipped. Before this check `import.meta.url` was rewritten to `https://cdn.skypack.dev/import.meta.url` (`src/load.test.ts`, "should leave import.meta untouched while rewriting imports").
3. Records with `d > -1` are dynamic `import()` and are left alone: their span is the whole argument, quotes included. The check used to be whether the characters around the span were `(` and `)`, which missed `import( "./x.js" )` and `import("./x.js", { with: ... })` and rewrote them to `import(https://cdn.skypack.dev/%22./x.js%22 ...)`, which is not valid JavaScript (`src/load.test.ts`, "should leave dynamic imports untouched while rewriting imports"). Rollup later passes a dynamic import's specifier to `resolveId` with the CDN module as importer, and `resolveId` resolves it against the URL that module was served from (#18, [[resolution]]; `src/index.test.ts`, "resolves a relative dynamic import against the CDN module's URL").
4. For each static import record, slice `main[s:e]`. Only a specifier matching `^\.{0,2}/` (`isRelativeReference`) is rewritten. A specifier with a scheme (`https://...`) and a bare package name are left alone (`src/load.test.ts`, "should preserve absolute URL imports", "should leave bare specifiers for resolveId").
5. A matching specifier is replaced with `new URL(specifier, dependency.url).href`. `dependency.url` is the `response.url` the module was served from, after redirects, so relative, root-relative (Skypack's `/-/pkg@ver/...` form) and protocol-relative (`//host/...`) specifiers resolve against it (`src/load.test.ts`, "should resolve relative and root-absolute specifiers against the response URL", "should resolve protocol-relative specifiers against the response URL's protocol"; protocol-relative since #20). When a custom `fetchImpl` returns an empty `url`, `resolveDependency` uses the requested CDN URL instead. Before that fallback, and while this used `url.resolve` from `node:url`, `url.resolve("", "./x.js")` returned the bare `x.js`, so the import was never pointed at the CDN ("should resolve against the requested URL when the response URL is empty").
6. The output is built in one pass: the unchanged slice before each rewritten specifier and its URL are pushed onto a `parts` array, the tail after the last one is appended, and `parts.join("")` runs once. This replaced a character array copied on every replacement, which was quadratic in the number of imports (#15; `src/load.test.ts`, "should rewrite a large module with many imports in linear time").

The result is returned as the module code. A module with nothing to rewrite comes back unchanged (`src/load.test.ts`, "should return module content as-is when no relative imports"; `src/integration.test.ts`).

## Why it is fragile

The rewrite depends on the lexer's offset semantics. es-module-lexer 3 changed the default entry's record fields, and with `s` and `e` undefined `slice` returned the whole module, so every import was replaced with the module source. Ten tests failed and the fix moved to the minimal entry (SferaDev/SferaDev#659, `CHANGELOG.md` 0.3.1). Any lexer upgrade should be checked against `src/load.test.ts` before merging.
