# Overview

rollup-plugin-import-cdn lets Rollup import ESM packages and URLs from a CDN and process them like local code, so they take part in tree-shaking (`README.md`). It is published to npm as `rollup-plugin-import-cdn`, dual ESM and CJS (`package.json` `exports`), with Rollup 3 or 4 as a peer dependency and `es-module-lexer` as its only runtime dependency.

## Module map

| File | Role |
| --- | --- |
| `src/index.ts` | `importCdn(options)`: picks a fetch implementation, wraps it in a per-build memo (the `responses` map), and returns the plugin object named `plugin-import-cdn` with `buildStart`, `resolveId`, `load` and `resolveImportMeta`. `buildStart` clears the memo and `moduleUrls`, the map from module id to the URL it was served from, filled by `resolveId` and `load`, that `resolveId` uses to resolve relative imports inside a CDN module ([[resolution]]) and `resolveImportMeta` uses as the value of `import.meta.url` in that module ([[import-rewriting]]). `isForeignId` matches `\0` virtual ids, `node:` and builtin modules, and absolute paths; `load` skips those ids, and so does `resolveId` unless the id is relative to a CDN importer |
| `src/load.ts` | `resolveDependency` ([[resolution]]) and `loadHook` ([[import-rewriting]]) |
| `src/integrity.ts` | `parseIntegrity`, `hasIntegrity` and `verifyIntegrity` for the `integrity` option, hashing with `node:crypto` |
| `src/types.ts` | `PluginOptions`, `FetchImpl`, `AvailableCDNs`, `Dependency`; all re-exported from `src/index.ts` |

## Options

`PluginOptions` in `src/types.ts`:

- `fetchImpl`: optional. Defaults to the global `fetch`; `importCdn` throws if neither exists, telling the user to run on a Node version with global `fetch` or pass `fetchImpl` (`src/index.ts`, `src/index.test.ts`).
- `priority`: CDNs to try in order, each a name from `availableCDNs` in `src/types.ts` (only `"skypack"`) or a function from specifier to URL. Defaults to `["skypack"]`. Since #31 `importCdn` throws at construction on any other entry, naming it, rather than failing on the first import (`src/index.test.ts`, "option validation"). A value that is not an array throws too, including a lone known name or function, which before #48 passed and then failed at the first import with `priorities.map is not a function`.
- `timeout`: optional milliseconds per request, default 30000, `0` disables it. The memo wrapper in `src/index.ts` passes an `AbortSignal` to `fetchImpl` and races the fetch plus `text()` against an unref'd timer, so a `fetchImpl` that ignores the signal still times out; the timeout error is a rejection that `resolveDependency` treats as a network error and moves to the next CDN. A negative, non-finite or non-number value throws at construction (`src/index.test.ts`, "request timeout").
- `versions`: a map from package name or full specifier to version. The built-in `skypack` entry inserts it after the package name, and custom `priority` functions receive it as their second argument ([[resolution]]).
- `cache`: optional directory. When set, a response for a URL whose path has `@x.y.z`, optionally with a `-prerelease` suffix, a `+build` suffix or both in that order (`src/load.test.ts`, "should cache the pinned URL"), followed by `/` or the end of the path (`isPinnedUrl`; the query and fragment are ignored, and `pkg@1.2`, ranges and tags do not match) is stored as `<sha256 of the URL>.json` (`url` after redirects, and `main`) and read back instead of fetching; writes go to `<file>.<pid>.<uuid>.tmp` and are renamed into place, and a failed write removes its temporary file; read and write failures warn, except a missing entry, and fall back to a fetch ([[resolution]], `src/load.ts`, `src/load.test.ts`). An empty or non-string value throws at construction (#31).
- `integrity`: optional map from URL to an SRI value (`sha256-`, `sha384-` or `sha512-` and a base64 digest, several space-separated). `resolveDependency` checks the body against the entries for both the requested URL and the final `response.url`, after a fetch and after a cache read, and throws `Integrity check failed for <url>: expected <value>, got <digest>` on a mismatch without trying the next CDN or writing the cache. A cache entry for a requested URL with an entry is only used when its recorded `url` equals the requested URL or has an entry too, since that `url` is the base for relative imports and the hash of `main` does not cover it; otherwise it is refetched. An entry keyed only by a final URL cannot protect a cache read, because the cache file names the final URL. The hash is over `text()` re-encoded as UTF-8, so a byte order mark or invalid UTF-8 in the served bytes makes a raw-byte digest disagree. As in SRI, only hashes using the strongest listed algorithm count. URLs without an entry are not checked. `importCdn` rejects a value that is not an object, a non-string entry, or a malformed hash at construction (`src/integrity.ts`, `src/integrity.test.ts`, `src/load.test.ts` "resolveDependency integrity", `src/rollup.test.ts`).

## Things the code does not do

Read from `src/index.ts` and `src/load.ts` on 2026-10-16:

- No cache across builds unless `cache` is set, and then only for versioned URLs. Within a build, the memo in `importCdn` fetches each URL once, so `resolveId` and `load` share one response (a rejection, timeouts included, is kept as well, so a hanging CDN costs one timeout per URL), and `buildStart` clears it so the next build fetches again (`src/index.test.ts`: "fetches a module once for resolveId followed by load", "refetches after buildStart").
- A non-OK response from one CDN moves on to the next. When no CDN succeeds and at least one answered non-OK, the build fails with an error listing every attempted URL with its HTTP status or network error; when every attempt was a network error, the plugin emits a Rollup warning with the same list and leaves the id unresolved; each failed attempt is also logged through `this.debug` (`src/load.test.ts`, `src/rollup.test.ts`).
- No fetch for ids that are not packages or URLs. `resolveId` and `load` return early for `\0` virtual ids, `node:` and builtin modules, and absolute POSIX or Windows paths (`isForeignId`, #14), and `resolveDependencyUrls` in `src/load.ts` returns no URLs for a local relative, root-relative or `file://` specifier, and the built-in `skypack` entry gives none for a specifier with a scheme such as `virtual:x` or a subpath import such as `#internal`; a relative specifier whose importer is a CDN module is the exception and resolves against that module's URL ([[resolution]]).
- No rewriting of bare specifiers inside a CDN module. `loadHook` rewrites only static imports that need a base URL (`isRelativeReference`: `./`, `../`, `/`, `//`) and leaves bare ones as written, so they return through `resolveId` with the configured `versions` and `priority` (#15, [[import-rewriting]]). Dynamic imports are left as written too and resolved in `resolveId`.
- Fetched code is only verified for URLs listed in `integrity`; anything else is bundled as the CDN served it.
- `src/load.ts` imports `node:crypto`, `node:fs/promises` and `node:path` for the on-disk cache, so the plugin runs where Rollup runs on Node, not in a browser build of Rollup. Specifiers resolve with the WHATWG `URL` global rather than `node:url`.
