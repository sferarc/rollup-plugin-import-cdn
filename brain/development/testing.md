# Testing

`pnpm test` runs vitest in a Node environment with `restoreMocks: true` (`vitest.config.ts`) over `src/*.test.ts`. Globals are off since #35, so each test file imports what it uses (`describe`, `it`, `expect`, `vi`, hooks) from `vitest`, and `restoreMocks` restores spies between tests. On 2026-10-28 the suite was 6 files and 249 tests (`it.each` cases counted separately), about two seconds wall clock on an idle machine; under heavy load the watch-mode rebuild test in `src/rollup.test.ts` can exceed the 5 s default timeout, so rerun it alone before treating a failure as real.

`src/index.test.ts` and `src/integration.test.ts` call hooks through `hooks(plugin)` from `src/test-utils.ts`, which unwraps the function or `{ handler }` form and calls it with Rollup's hook types and a fake context from `fakeContext()` that records `warn` and `debug` into the returned `logs` (`fakeContext({ withDebug: false })` mimics Rollup 3 before 3.25), so a hook signature change fails typecheck in the tests. Only test files import it, so it stays out of `dist` and knip sees it as used.

Every test uses a mock `fetchImpl`; nothing touches the network. Watch mode runs with Rollup's `cache` on (watch cannot turn it off), so a rebuild resolves only the entry again; the `buildStart` reset is covered by the plain two-build test above, and the plugin's `cache` option is not covered under watch. Real CDNs and the network are not covered either. The local suite runs against the catalog Rollup pin in `pnpm-workspace.yaml`; CI also runs it on Rollup 3.0.0 since #71 (see [[ci]]), where the `onLog` test is skipped because `logLevel` and `onLog` need 3.25.
