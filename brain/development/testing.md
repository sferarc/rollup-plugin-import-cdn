# Testing

`pnpm test` runs vitest in a Node environment with `restoreMocks: true` (`vitest.config.ts`) over `src/*.test.ts`. Globals are off since #35, so each test file imports what it uses (`describe`, `it`, `expect`, `vi`, hooks) from `vitest`, and `restoreMocks` restores spies between tests. On 2026-10-19 the suite was 5 files and 192 tests (`it.each` cases counted separately), about two seconds wall clock.

| File | Covers |
| --- | --- |
| `src/index.test.ts` | `importCdn`: plugin name, the fetch fallback and the error without one, both hooks, `priority` and `versions`; option validation that throws on an unknown CDN name, a bad `priority` entry, a non-array `priority` or an empty or non-string `cache` (#31), an `integrity` value that is not an object or holds a malformed hash, a `fetchImpl` that is not a function; the `timeout` option ("request timeout", #39: a hanging request or body read fails over to the next CDN, the `signal` passed to `fetchImpl` is aborted, the 30 second default under fake timers, `0` passing no init, and negative, non-finite, string or over 2147483647 values rejected while 2147483647 itself works); fetch memoisation (one fetch for `resolveId` then `load`, a refetch after `buildStart`, #14); importer-relative specifiers (relative, root-relative and protocol-relative imports resolved against the CDN module's redirected URL, local importers left to Rollup, importer URLs forgotten after `buildStart`); foreign ids (`\0virtual`, `node:fs`, `fs`, Windows paths) skipped without a fetch; an unresolvable package warning through the hook context, not `console`, and debug messages dropped on a context without `this.debug` |
| `src/load.test.ts` | `resolveDependency` ([[architecture/resolution]]) and `loadHook` ([[architecture/import-rewriting]]) directly, including the failure message that lists every attempted URL with its status or network error (#25) and the lex error that names the module and URL (#27); the on-disk cache in a temp directory: pinned URLs and subpaths served without a refetch, the cache shared between plugin instances, unpinned URLs, error responses and malformed entries refetched, concurrent writes leaving one valid entry, nothing cached without the option (#21), and a warning when an entry is not JSON, a write fails or the directory cannot be created, with no temporary file left behind (#29); the `integrity` option: matches by requested or final URL, a mismatch that throws without trying the next CDN or writing the cache, a tampered cache entry that fails, and a cache entry whose recorded URL was changed being refetched |
| `src/integration.test.ts` | realistic module shapes against a mock CDN: scoped packages, dynamic imports, re-exports, fallback chains, network failures, malformed source; two real `rollup()` builds on a CDN entry: a dynamic import relative to a CDN module (#18) and protocol-relative imports (#20) |
| `src/integrity.test.ts` | `parseIntegrity` (each algorithm, several hashes, malformed values rejected), `hasIntegrity`, and `verifyIntegrity` (match, mismatch message, any-of and strongest-algorithm semantics, URLs without an entry) |
| `src/rollup.test.ts` | real `rollup()` builds of a local entry file in a temp directory against a mock CDN graph: a bare specifier that redirects to a pinned path, its relative and root-relative static imports and a bare import of a second package, a direct URL import and a local relative import read from disk all land in one chunk; an entry given relative to cwd without `./` (`input: "dir/index.js"`, written to a temp directory under cwd) is read from disk with no fetch; a `virtual:greeting` import is left to a plugin listed after this one, with no fetch, and so is a `virtual:` entry whose name is too long to stat; `import.meta.url` in a CDN module becomes the URL it was served from while the local entry keeps its own, and still does on a second build with the same plugin and the first build's `cache`; an unused export of a CDN module is tree-shaken; each URL is fetched once per build even when imported twice; a second build with the same plugin instance refetches every URL; a 404 from every CDN fails the build with each attempted URL in the message; network errors on every CDN reach `onLog` as one debug log per URL and one `PLUGIN_WARNING` from `plugin-import-cdn`; an `integrity` entry lets a matching URL build and fails a mismatching one. Each test asserts the global `fetch` was never called |

`src/index.test.ts` and `src/integration.test.ts` call hooks through `hooks(plugin)` from `src/test-utils.ts`, which unwraps the function or `{ handler }` form and calls it with Rollup's hook types and a fake context from `fakeContext()` that records `warn` and `debug` into the returned `logs` (`fakeContext({ withDebug: false })` mimics Rollup 3 before 3.25), so a hook signature change fails typecheck in the tests. Only test files import it, so it stays out of `dist` and knip sees it as used.

Every test uses a mock `fetchImpl`; nothing touches the network. Multiple entry points, other output formats such as CJS, `bundle.write()`, watch mode and the on-disk cache inside a build stay untested. So do real CDNs and the network, and Rollup 3: `package.json` accepts `rollup` `^3.0.0 || ^4.0.0` as a peer, but the suite only runs against the catalog pin in `pnpm-workspace.yaml` (4.64.5 on 2026-10-15).
