# rollup-plugin-import-cdn

## 0.5.0

### Minor Changes

- c90953f: Default `priority` to `["esm.sh"]` instead of `["skypack"]`. Skypack served React 17 for `import "react"` and for pinned React 18 and 19 versions, while esm.sh answers an unknown version with a 404 and serves pinned builds. Builds that rely on the default now fetch from `https://esm.sh/`, so `cache` entries are fetched again and `integrity` keys for `cdn.skypack.dev` URLs no longer match. Set `priority: ["skypack"]` to keep the old behaviour.

## 0.4.0

### Minor Changes

- f5e9f29: Add `"esm.sh"` as a built-in `priority` entry. It builds `https://esm.sh/<name>@<version>/<subpath>` from `versions` the way `"skypack"` does, and skips specifiers with a scheme.
- 6e5cfb2: Add an opt-in `cache` directory option that stores responses for URLs pinned to an exact version, so repeat builds do not refetch them.
- 98d6b0e: Add a `timeout` option, 30 seconds by default, so a CDN that accepts the connection but never answers fails over to the next CDN in `priority` instead of stalling the build. Set it to `0` to wait indefinitely as before.
- 165990f: Add an `integrity` option that maps CDN URLs to Subresource Integrity hashes. A fetched or cached module whose source does not match fails the build, so a compromised CDN or a modified cache file cannot slip into the bundle.
- 6c1f885: Add `"jsdelivr"` as a built-in `priority` entry. It builds `https://cdn.jsdelivr.net/npm/<name>@<version>/<subpath>/+esm` from `versions` the way `"skypack"` does, and skips specifiers with a scheme.
- 371dbe0: Let a custom `priority` function return `undefined` to skip a specifier. The next entry is tried without a request, and a specifier every entry skips is left to the next plugin with no warning. Before, the function had to return a URL, and `undefined` was passed to `fetchImpl`, which with the global `fetch` failed as a network error and was warned about.

### Patch Changes

- a8dae4a: Warn when an on-disk cache entry cannot be read, is not valid JSON or has the wrong shape, and when writing an entry fails, naming the cache file and the CDN URL. A missing entry stays silent, and every cache failure still falls back to a fetch.
- f2618fa: Only trust a version pinned in the URL path when deciding what to cache, ignore cache entries whose `url` is not an http(s) URL, and give each cache write its own temporary file so concurrent builds sharing a cache directory do not collide.
- 6986055: Cache URLs pinned to a version with both a prerelease and a build suffix, such as `pkg@1.2.3-rc.1+build.5`, which were refetched on every build.
- 5b9fbb5: Cache Skypack's module paths, such as `/-/lodash@v4.17.21-<hash>/dist=es2019,mode=imports/optimized/lodash.js`. With `cache` set only the stub a pinned Skypack URL returns was stored, and the code it imports was refetched on every build.
- 55b37c8: Cache Skypack's pinned URLs, such as `https://cdn.skypack.dev/pin/lodash@v4.17.21-<hash>/mode=imports/optimized/lodash.js`. With `cache` set only the module that URL imports was stored, so every build fetched the pinned URL again and an offline build failed on it.
- 62065d9: Point `import.meta.url` inside a CDN module at the URL the module was served from. Bundled, it used to name the output chunk, so `new URL("./mod.wasm", import.meta.url)` in a package fetched from the CDN resolved to a file next to the bundle instead of the CDN. `import.meta.url` in local modules is unchanged.
- cbcd2e4: Put CDN modules on the output sourcemap's ignore list, as Rollup does for `node_modules`, so browser devtools skip them when stepping through code. Applies when `output.sourcemapIgnoreList` is unset, on Rollup 3.16 or newer and under Vite; a `sourcemapIgnoreList` of your own still decides for every source.
- 1938411: Name each CDN module in an output sourcemap by the URL it was served from. Rollup resolved the module id against the working directory, so `sources` held paths such as `../https:/cdn.skypack.dev/...` or `../lodash` that no tool could open. A `sourcemapPathTransform` set in the output options still applies to local sources.
- b66cadf: Leave an entry given relative to the working directory, such as `input: "src/index.js"`, to Rollup when that file exists. It used to be treated as a package name and fetched from the CDN, so the build failed with HTTP 404.
- 1337558: Bundle a CDN module once when it is reached both by a specifier that redirects to a URL and by that URL directly. Each used to become its own module, so the same code was bundled twice and module-level state such as a singleton was split between the copies. Two specifiers now share one module when they were served from the same final URL with an identical body.
- 2c6a7ce: Resolve relative imports against the requested CDN URL when a custom `fetchImpl` returns a response with an empty `url`, instead of leaving them unresolved, and use the WHATWG `URL` API in place of the deprecated `url.resolve`.
- 04cf36a: An entry id that cannot be a file name, such as a `virtual:` id with a segment over 255 characters, is now passed on to the next plugin instead of failing the build with `ENAMETOOLONG` from the check for a cwd-relative entry.
- c52ca72: Resolve a relative import inside a CDN module by its string value, so an escaped specifier such as `"./\u00fc.js"` fetches `%C3%BC.js` instead of `/u00fc.js`, and a `'` in a single-quoted specifier no longer breaks the rewritten import.
- 803e533: Fail the build with the URL and HTTP status when the CDN responds with an error, instead of bundling the error page as the module.
- c41ea26: Reject a `fetchImpl` that is not a function when the plugin is created. A string or object used to pass and fail every request as a network error, so each CDN import was only warned about and left out of the bundle as an unresolved import.
- fdf3a75: Treat an HTML page served with HTTP 200, such as a captive portal or a CDN's soft error page, as a failed attempt. The plugin now tries the next CDN, fails the build naming the page URL when none succeeds, and neither caches that page under a pinned URL nor uses one cached by an earlier version, so one bad network no longer breaks every later build. Under `vite dev` such a response is fetched again on the next page load.
- 56113ac: Keep `import.meta.url` in a CDN module pointed at its served URL on a rebuild from Rollup's cache, as in watch mode. The rebuild reused Rollup's cached resolutions, skipped the plugin's `resolveId` for unchanged modules, and left `import.meta.url` naming the output chunk again.
- bda6b82: Resolve relative and root-relative dynamic imports inside CDN modules against the URL the module was served from, instead of letting Rollup look for them on disk.
- 1d01f2e: Warn at the end of a build for each `integrity` entry that no URL fetched in that build matched. Bumping a version in `versions` without updating the `integrity` key that names the old URL left the new module unchecked with no sign of it; the warning names the stale key. The Vite dev server is skipped, since it loads modules on demand.
- 6712f0b: Throw when the plugin is created with an `integrity` key that is not an absolute URL, such as `lodash` or `//cdn.skypack.dev/lodash@4.17.21`. Entries are matched against the URLs the plugin fetches, so such a key never matched and the module was bundled unchecked.
- 2012df6: Treat a jsDelivr `+esm` file that jsDelivr could not bundle as a failed attempt. jsDelivr serves it with HTTP 200 as a module that throws `Failed to bundle using ...`, so the build used to pass and the bundle threw at runtime. The plugin now tries the next CDN, fails the build with jsDelivr's reason when none succeeds, and neither caches that module under a pinned URL nor uses one cached by an earlier version.
- 9bd93e5: Leave every dynamic `import()` in CDN modules untouched. One with spaces inside the parentheses or with import attributes, such as `import("./x.js", { with: { type: "json" } })`, was rewritten with its quotes inside the URL, which made the module fail to parse.
- 34c4182: Leave `import.meta` in CDN modules untouched. It was rewritten to a URL such as `https://cdn.skypack.dev/import.meta`, which made any module that reads `import.meta.url` fail to parse.
- fc8e292: Leave bare specifiers in CDN modules untouched so they go back through `resolveId` and pick up the configured `versions` and `priority`. They were resolved against the module URL, which turned `import x from "react"` into a path under the importing package. The import rewrite also runs in linear time now, instead of copying the whole module once per import.
- 34fbc51: Fetch each CDN module once per build instead of once in `resolveId` and again in `load`, and skip Rollup virtual ids, Node builtins and absolute paths without contacting the CDN.
- 8d3dca1: Declare the supported Node range as `>=22.12.0` in `engines`, so package managers warn on older Node at install time instead of the build failing at runtime.
- 8197efb: Throw a clear error when `importCdn` is created with an unknown CDN name or invalid entry in `priority`, or with an empty `cache` directory, instead of failing later inside a Rollup stack trace. The missing-fetch error now says to run on a Node version with a global `fetch` or pass `fetchImpl`.
- 848a5c3: Name the module and the URL it was fetched from when its source cannot be lexed, and say so when the CDN returned an HTML page instead of a module. The lexer's error stays available as `cause`.
- 95cf0de: Throw at construction when `priority` is not an array. A single CDN name such as `priority: "skypack"` or a lone function used to be accepted and then fail at the first import with `priorities.map is not a function`.
- d3ba447: Fail the build with a message naming the `priority` entry and the specifier when a custom `priority` function returns something other than an absolute URL or `undefined`. A relative path such as `"lib.js"` used to reach `fetch`, which rejected it as a network error, so the import was left unresolved behind a warning; with a `fetchImpl` that accepted it, the module's own relative imports could not be resolved.
- e3bfe6d: Resolve protocol-relative imports (`//host/path.js`) inside CDN modules against the module's URL instead of leaving them unresolved.
- 6086b21: List every attempted CDN URL with its HTTP status or network error, including the underlying cause, when a dependency fails to resolve, instead of logging network errors only at debug level.
- 9577122: Report warnings through Rollup instead of `console.warn`, so `onwarn` and `onLog` can filter them or turn them into errors. Each failed CDN attempt is also logged at debug level (`logLevel: "debug"`, Rollup 3.25 or later) before the next CDN is tried.
- 21f4412: Stop requesting specifiers with a scheme, such as `virtual:greeting` or `data:...`, from Skypack, which only serves npm package names. With this plugin listed before the plugin that owns a `virtual:` module, the build used to fail with HTTP 404 from `https://cdn.skypack.dev/virtual:greeting`. A custom `priority` function still receives these specifiers.
- 95fbe16: Treat a Skypack build error as a failed attempt. Skypack answers a package it cannot build with HTTP 200 and a module that throws on import; the plugin now tries the next CDN, fails the build naming the error URL when none succeeds, and neither caches that response nor uses one cached by an earlier version.
- 08ef3cd: Treat a Skypack response for an exact version that serves a different version as a failed attempt. Skypack has been answering `react@18.2.0` with React 17.0.1; the plugin now tries the next CDN, fails the build naming the served version when none succeeds, and neither caches that response nor uses one cached by an earlier version.
- 8969df6: Stop requesting package.json subpath imports such as `#internal` from Skypack. A specifier starting with `#` is never an npm package name, and the plugin used to request `https://cdn.skypack.dev/#internal`, which drops everything after `#` as a URL fragment, so the build failed or bundled the wrong response instead of leaving the import to the plugin listed after it. A custom `priority` function still receives these specifiers.
- 1f64fe8: Reject a `timeout` above 2147483647 when the plugin is created. Node runs a longer `setTimeout` after 1ms, so a value such as `Number.MAX_SAFE_INTEGER` timed out every request at once and failed over through every CDN.
- ce1ce52: Read only the `versions` option's own entries. With any `versions` set, a package named after an `Object.prototype` member, such as `constructor`, was fetched from `constructor@function Object() { [native code] }`, and a custom `priority` function received that function as its version.
- 7266f14: Keep the `versions` pin for a bare specifier with a query or fragment, such as `preact?dev`, and place the version before the query, so it resolves to `preact@10.19.3?dev` instead of dropping the pin. The `jsdelivr` entry puts the query after `/+esm`.
- 1ba18df: Apply `versions` to subpath and scoped specifiers by package name and place the version after the package name, so `react-dom/client` with `versions: { "react-dom": "18.2.0" }` resolves to `react-dom@18.2.0/client`. Custom CDN functions now receive the pinned version as a second argument.
- b48065d: Throw when the plugin is created with a `versions` option that is not an object, or with an entry that is not a non-empty string. A string or array used to pin nothing without a word, and a number such as `18.10` reached the CDN URL as `18.1`.
- 7be21be: Stop fetching `index.html` from the CDN when `vite dev` starts in a root without one. Vite resolves `index.html` as an entry at startup, and the plugin treated it as a package name and requested it from every CDN in `priority`. Ids ending in `.html` that are not URLs are now left to other resolvers.
- 9c979cf: Under `vite dev`, also retry a CDN request that answered HTTP 408, 429 or 5xx on the next page load. Only network errors and timeouts were retried, so a CDN outage that returned 503 kept failing the import until the server restarted. A 404 is still kept for the server's lifetime.
- eb99c29: Retry a failed CDN request on the next page load under `vite dev`. The dev server runs `buildStart` once, so a network error or timeout was kept for the whole session and every reload failed to resolve the import until the server restarted.
- 67bed9e: Point `import.meta.url` inside a CDN module at the URL it was served from under Vite too. Vite 8 does not apply Rollup's `resolveImportMeta` hook, so `new URL("./mod.wasm", import.meta.url)` in a package fetched from the CDN resolved against the output chunk in `vite build` and against the dev server in `vite dev`. The plugin now writes the URL into the module when it loads it under Vite; Rollup builds are unchanged.
- fbc2603: Type `importCdn()` so that Vite 8's `Plugin` type accepts it. It returned Rollup's `Plugin` type, whose hook context Vite 8 (typed against Rolldown) does not match, so a TypeScript `vite.config.ts` needed `importCdn() as unknown as PluginOption`. The cast is no longer needed, and the plugin is still assignable to Rollup 3 and 4's `Plugin`.
- e4c1653: Bundle URL imports under Vite. Vite's resolver ran before the plugin and marked every `https://` import external, so a direct URL import and the absolute URLs the plugin writes into CDN modules stayed as runtime imports instead of being bundled and tree-shaken. The plugin now sets `enforce: "pre"`; under Vite it still lets Vite resolve bare names first, so installed packages and Vite's own modules are unchanged, and it only loads ids it resolved itself, so another plugin's virtual module no longer reaches the CDN.
